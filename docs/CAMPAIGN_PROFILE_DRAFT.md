# Новый профиль кампании — этап B

Этот формат использует [кампания по основному адресу игры](CAMPAIGN_RUNTIME.md).
Ранее начатая кампания читается по тому же ключу `lighthouse.campaign.v1`.
Докампанейские данные хранятся отдельно под ключом `lighthouse.save.v1`.

## Что хранится

`CampaignProfile` версии 1 хранит осколки и жемчуг, купленные узлы каталога,
побеждённые и выбранную сюжетную ночь, выбранную линзу и способность,
отмеченные вступления, общий инвентарь и планы карт. Новый профиль начинает
с первой ночи, базовой линзы и без покупок, устройств и активной способности.
Доступ к главам и принадлежащему оснащению выводится из побед и покупок.

Покупки сохраняются по ID единого каталога 256 узлов: отдельной копии списка
открытых линз или типов устройств нет. Чтение проверяет ссылки и зависимости,
но само не выполняет покупки, не определяет их цены и не начисляет награды.
Покупки проверяет прогрессия кампании перед записью, а награды — обработка исхода.

## Расстановка при смене карты

Инвентарь хранит ID, тип, состояние корпуса в базовых единицах и заряды
экземпляров. План каждой карты хранит только ID и мировые координаты.
Один экземпляр может быть в нескольких планах, но в бою будет использоваться
только план выбранной карты. Новая карта показывает пустое поле и весь запас.
После возврата на старую карту берутся её координаты и текущее состояние того
же экземпляра, а не его прежняя копия. Размещение и снятие бесплатны.

Корректный файл может содержать координаты, которые стали недопустимыми после
изменения геометрии. Подготовка явно возвращает ошибку для такой позиции,
оставляя её на плане. Готовое к размещению устройство можно переставить,
а любой экземпляр — убрать в запас по ID. Несколько ошибочных позиций можно
исправлять по одной. Запоздавшая команда для другой карты не меняет её план.
Проверка расстановки не означает, что выбранная ночь уже готова к запуску.

## Запись и границы

Репозиторий получает `SaveStore` извне. Он записывает подготовку, старт и исход,
публикует подтверждённое состояние и позволяет повторить или отменить
неподтверждённую операцию. Если запись прошла, но ответ потерялся, сверка
принимает записанное без второго изменения. При конфликте данные не затираются:
неподтверждённое изменение можно отменить и заново загрузить записанный профиль.
Даже команда без изменений не подтверждается на устаревшем снимке.
Повторный запуск читает фактическую запись; повреждённая запись не сбрасывается
молча. Сверка не заменяет блокировку записи профиля между вкладками.

При запуске и исходе проверяется соответствие ночи, карты, оснащения и
снимка устройств. Итоговые HP в хранилище остаются в базовых единицах.
Состояние экрана, камеры и объекты Phaser не пишутся.

```text
pnpm exec vitest run tests/campaignProfileCodec.test.ts tests/campaignPreparation.test.ts tests/campaignProfileRepository.test.ts
```
