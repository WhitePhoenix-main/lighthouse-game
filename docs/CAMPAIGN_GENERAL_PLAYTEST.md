# Плейтест общих эффектов этапа A

Сравниваем «Быстрый разворот» и «Стабилизацию поля» с базой и между рангами I и II. Параметры предварительные. Протокол готов к проведению, карточка пустая. [Правила боя и критерии плейтеста](../GAME_DESIGN.md#проверка-игровой-основы) · [Кандидатные параметры](CAMPAIGN_GENERAL_DRAFT.md) · [Технический отчёт этапа A](../reports/CAMPAIGN_STAGE_A_GENERAL.md)

## Запуск

Из `E:\WebGames\lighthouse-game` запустить `pnpm dev`. При первой установке сначала выполнить `pnpm install --frozen-lockfile`. Открыть `http://127.0.0.1:5173/tests/browser/campaign-general-frame.html`. Если Vite выбрал другой порт, взять адрес из строки `Local` и добавить к нему `/tests/browser/campaign-general-frame.html`.

Стенд сразу открывает контрольный бой с seed 42. Профиль только в памяти, звук отключён. В верхней панели выбрать «Разворот» или «Поле» и ранг «Без улучшения», «I» или «II». Выбор любого из них запускает новый бой. Кнопка «Начать заново» повторяет текущую пару. [Страница стенда](../tests/browser/campaign-general-frame.html) · [Код сценариев](../tests/browser/campaign-general-frame.ts)

## Порядок прогонов

На шесть участников дать по одной строке в порядке записи. `0` означает «Без улучшения». Каждый проходит оба сценария по три раза. Смена первого сценария и порядка рангов распределяет эффект знакомства со стендом.

| Участник | Сценарии по порядку | Ранги для «Разворота» | Ранги для «Поля» |
| --- | --- | --- | --- |
| 1 | Разворот → Поле | 0 → I → II | II → I → 0 |
| 2 | Поле → Разворот | I → II → 0 | 0 → II → I |
| 3 | Разворот → Поле | II → 0 → I | I → 0 → II |
| 4 | Поле → Разворот | II → I → 0 | 0 → I → II |
| 5 | Разворот → Поле | 0 → II → I | I → II → 0 |
| 6 | Поле → Разворот | I → 0 → II | II → 0 → I |

Для сравнения взять один компьютер, мышь и один размер окна. Наблюдатель выставляет условия и объясняет только действия. Ранги видны в панели, поэтому сначала записать, на какой видимый признак ссылается игрок, и затем обсудить числа и правила. Перед каждым прогоном нажать «Начать заново», держать курсор над панелью и выполнить одно действие около `t=1 с` по строке стенда. Повторять условия только после завершения тройки и отмечать повтор или подсказку.

1. **Разворот.** Нажать «Развернуть на 180°». Следить, как фактический луч доходит до нового направления. Записать, где игрок заметил ускорение, плавным ли показался переход и в какой момент он счёл луч готовым принять другую угрозу. После тройки спросить, чем II отличался от I и изменило бы это решение добить почти поверженную цель или срочно перевести луч на другой подход. Причину записать словами игрока. Ответ о выборе здесь гипотетический.
2. **Поле.** Убедиться, что поле полное, затем нажать «Истощить поле». Стенд ставит один генератор и обнуляет запас одним искусственным ударом. Дождаться первого роста поля и проследить за ним в первые секунды. Попросить игрока описать, когда защита пропала, чего он ждал до возврата и что, по его мнению, меняется между базой, I и II. Наблюдатель может сверить объяснение по строке `поле / задержка / стабилизация`. Ожидаемое поведение для наблюдателя — обычная задержка, затем постепенное восстановление. У I и II временно выше скорость, а запас начинает расти после той же задержки. Записать, если игрок принял ускорение за мгновенный возврат или сокращение ожидания. [Правила общего поля](../GAME_DESIGN.md#генераторы-и-энергетический-щит) · [Условия стабилизации](CAMPAIGN_GENERAL_DRAFT.md)

## Границы проверки

- **Синтетический бой.** Один неподвижный призрак с большим запасом здоровья позволяет сравнить движение луча и возврат поля. Тактический выбор между живыми угрозами, повторные удары по защищаемым целям и польза на геометрии глав требуют боевого сценария с подходящим давлением. Времена из отчёта получены симуляцией. Здесь записываем наблюдения игрока, а поле `t` используем для одинакового старта действия.
- **Физический телефон.** Отдельно проверить на реальном устройстве в портрете и альбоме, читаются ли луч и состояние поля, удобно ли нажимать кнопки и наводиться пальцем в бою. Указать модель, браузер, ориентацию, способ ввода и фактически выполненные действия. Историческая проверка стенда мышью и эмуляция размеров подтверждают только проверенные браузерные условия.

## Следующее решение

Рабочий порог для каждого эффекта — минимум четверо из шести участников без подсказки описали, что меняет эффект, и назвали конкретное отличие II от I. Среди этих участников должны встретиться оба порядка сценариев и разные первые ранги. Если порог пройден, перенести кандидат на геометрию главы и проверить с конкурирующими угрозами, а для поля — также с повторными попаданиями. Если игроки путают сам эффект, уточнить его визуальную обратную связь. Если эффект понятен, а I и II сливаются, проверить различимость параметров и повторить сравнение. Решение о балансе и покупках принимать после проверки в бою.
