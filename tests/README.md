# Наборы проверок

Тесты и браузерные стенды принадлежат репозиторию. `.gitignore` больше не
определяет, какие тесты запускаются; состав наборов явно задан в Vitest-конфигах.

| Команда / область | Назначение |
| --- | --- |
| `pnpm test`, корневые `*.test.ts` | Рабочие регрессионные сценарии, включая луч, сохранения, устройства и интерфейс |
| `pnpm test:audits`, `audits/` | Долгие моделирования баланса; результаты только в `test-results/balance/` |
| `pnpm test:legacy`, `legacy/` | Сохранённые ожидания с известными исходными несовпадениями, требующие ревизии |
| `pnpm test:legacy:baseline` | CI-проверка точного списка известных ошибок; новые ошибки, пропуски тестов и исчезнувшие сценарии блокируют слияние |
| `browser/` | Изолированные HTML/TS-стенды; команды в [tools/README.md](../tools/README.md) |
| `helpers/` | Общие данные и вспомогательные функции тестов |

`campaignPurchaseBudget.test.ts` проверяет кандидатные цены и условия 256
покупок, бюджет 56 первых побед и ремонт после серии поражений. Это расчёт
по каталогу, не симуляция 56 боёв; методика в [бюджете кампании](../docs/CAMPAIGN_BUDGET_DRAFT.md).

`campaignFoundation.test.ts` и `campaignControlMaps.test.ts` проверяют
идентификаторы и кандидатный доступ, размещение и повторяемость боя на трёх
контрольных картах без подключения новых глав к игре.
`campaignGroundRoutes.test.ts` проверяет габарит наземной цели по всему пути,
включая регрессию берега с `seed = 7`, и один случайный выбор на появление.

Проверки `campaignProfileCodec.test.ts`, `campaignProfileRepository.test.ts` и
`campaignPreparation.test.ts` используют только [новый профиль кампании](../docs/CAMPAIGN_PROFILE_DRAFT.md):
формат, смену карт и подтверждение записи в подставное хранилище.

Матрицы локализации и сравнения линз в `stage2Economy.test.ts` и
`stage3Economy.test.ts` разбиты на именованные параметризованные случаи.
Каждая комбинация ночи, seed и режима вызова волн сравнивает все нужные линзы;
профиль для неё загружается из отдельной копии заработанного сохранения.
Это сохраняет покрытие и стандартный тайм-аут 5 секунд на тест, не объединяя
десятки боёв или сотни переводов под одним лимитом времени.

Полный диагностический запуск до реорганизации 18 ноября 2026: 113 файлов,
1636 тестов, 1406 прошли и 230 не прошли. В основной набор возвращены
работающие ранее скрытые проверки. Три генератора отчётов отделены, чтобы
обычный `pnpm test` не переписывал сохранённые отчёты в `reports/`.

36 файлов с исходными ошибками перенесены целиком в `legacy/`: это сохраняет
в том числе полезные проверки внутри смешанных suites. Перенос не доказывает,
что каждое их ожидание устарело или ошибка несущественна. При исправлении
сценария его следует вернуть в основной набор, сверив правила с GAME_DESIGN.
Имена и число исходных ошибок зафиксированы в
[манифесте legacy](legacy/BASELINE.json). Успех основного набора не означает
успех legacy или подтверждение чисел старого баланса.

При подготовке beta 0.1 исправлены недостающие английские переводы, а семь
проверок `localization.test.ts` возвращены в основной набор. Исторический
манифест сохраняет первоначальные ошибки; поле `restoredTo` отмечает suites,
которые снова проверяются основным CI. Текущий legacy: 35 файлов, 627 тестов,
398 проходят, 229 остаются с известными ошибками. Проверка baseline не объявляет
их исправленными: она обнаруживает изменение состава ошибок и потерю покрытия.
Полный список тестов хранится в `legacy/TEST_IDENTITIES.json`; отдельный reporter
также блокирует ошибки hooks, загрузки suites и необработанные исключения.
