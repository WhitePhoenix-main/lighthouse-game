# Поле подготовки: просторная подложка и адаптивная камера

Рабочая версия 5, 17 ноября 2026. Отдельный дизайн-макет, не код работающей игры.

- [Общий вид](preview-portrait.png), [выбранная пушка](preview-selected.png),
  [широкий вид](preview-landscape.png), [отдаление к бою](preview-battle.png).
- [Интерактивный макет](../camera-demo.html): одна сцена, явный крупный план,
  автоматический охват областей и каталог устройств. Размещение и бой не выполняются.

## Источники и геометрия

`scene-data.js/json` — снимок настоящей базовой конфигурации `broken-shore` из
`NIGHT_CATALOG`: дальность луча 300, появление 365, радиус мира 400, пушка 160,
корпус барьера 26. Снимок без улучшений профиля; пример расстановки не берётся
из сохранения пользователя. При интеграции нужен актуальный `ApplicationView.config`.

`camera-geometry.js` — единая проекция `(x, y × 0.7)`, границы объектов/областей,
fit и обратное преобразование. Наклон и художественные размеры предварительные.
Общий план включает полные области света, появления, выбранного устройства и
спрайты с отступом 24 CSS px. У генератора область относится к общему полю маяка,
у барьера показывается тело. Крупный план явный, а дальний вид не приближает камеру.
Мировые координаты, текстуры и пропорции спрайтов остаются теми же.

`world-preview.js` использует эти функции для canvas, выбора и resize/DPR.
Контуры не вшиты в подложку. Появление показывается общим кольцом, без раскрытия
конкретных точек, направлений и неизвестных видов. Это не круговой урон луча.

## Изображения

Исходники созданы встроенным ImageGen: исходные запросы — [prompts.json](prompts.json),
новая кромка — [shore-revision-prompt.txt](shore-revision-prompt.txt).

| Файл | Назначение |
| --- | --- |
| `terrain-coast-irregular-v1.png` | Актуальная 1536×1024 подложка с неровными слоистыми уступами по пользовательскому референсу; без вшитых объектов. Границы рисунка X ±1500, Y ±1428.57 сохраняют запас. |
| `terrain-padded.png` | Предыдущий вариант с более прямой границей, сохранён для истории. |
| `lighthouse-main.png` | Прозрачная производная по маяку из реального `sprites/background.png` главной; исходное меню не изменено. |
| `props-atlas.png` | Прозрачный атлас 2×2: пушка слева сверху, барьер справа сверху, причал слева снизу, четвёртая ячейка пустая. |

`asset-inspection.json` содержит размеры и границы alpha≥128. Рендерер вырезает
рамки при рисовании и сохраняет пропорции. Прозрачность проверена, в том числе
пустая четвёртая ячейка. Причал стоит в (0,110), рядом с маяком; это декорация,
не цель, препятствие или новый режим. Его точное место можно менять в данных.

`shore-reference-user.png` — предоставленный пользователем референс неровной
каменной границы. Он используется для обсуждения и генерации, не как текстура
самой сцены. Уступы и небольшие изгибы разрешены: идеальная прямая не является
художественным ограничением. `currentGameLandBoundary` в данных честно сохраняет
нынешнюю прямую `shoreX=0`; `visualCoastline` описывает новый рисунок. Пока нет
реальной установки и маски этой кромки. При интеграции графику и допустимость
расстановки нужно связать одним описанием берега, чтобы они не противоречили друг другу.

## Проверка и воспроизведение

Из корня репозитория, с существующими зависимостями pnpm:

```powershell
node art/concepts/preparation-2026-11-17/world-v2/refresh-scene-data.mjs
node --test art/concepts/preparation-2026-11-17/world-v2/camera-geometry.test.mjs
node art/concepts/preparation-2026-11-17/world-v2/prepare-preview-layouts.mjs
& ./art/concepts/preparation-2026-11-17/world-v2/render-previews.ps1
```

Первая команда читает текущий контент через Vite без HTTP-сервера. Последняя
строит PNG через System.Drawing на Windows: позиции, размеры и области берутся
из того же геометрического модуля, а подписи — из глифов меню. Это экспорт поля,
не скриншот браузерной страницы. При замене исходников графики нужно перепроверить
alpha-рамки в `asset-inspection.json`.

Прошли 16 тестов: полные области на viewport 360×360, 390×390, 844×280 и 1280×400;
выбор у границы, одинаковые координаты во всех режимах, отдаление, пропорции,
покрытие подложкой, DPR/resize и отсутствие смены источников. Fake DOM используется
только для проверки рендерера, не считается тестом браузера или телефона.
Независимое ревью блокирующих замечаний не нашло. PNG просмотрены визуально;
расположение причала после этого уточнено, чтобы он читался у земли, а не у башни.
Браузерный просмотр ранее недоступен, проверка на реальном телефоне не выполнена.
